# V4.9.0 内网安全审计与上线验收

审计范围包括仓库代码、迁移、生产部署模板和隔离 TEST。公司内网的实际防火墙、网关 ACL、TLS 证书、存储加密和备份计划由现场运维取证。

## 防火墙与网络边界

| 审计发现 | 内网风险 | V4.9.0 措施 |
| --- | --- | --- |
| 生产模板的应用端口绑定回环地址，业务通过 HTTPS 入口访问 | 可到达入口的终端能够发起登录请求，失陷终端可能滥用凭证 | 公司服务器现有防火墙管理业务终端的访问范围。WMS 继续执行登录和权限校验。 |
| 应用已有登录限流 | 异常请求或连接激增可能影响库区作业 | 应用沿用既有登录限流。Nginx 模板记录应用请求编号，便于关联入口与应用日志。 |

公司网络运维统一管理业务终端、数据库和运维入口之间的连通范围。SAP EWM 建议按网络段划分系统并由防火墙保护。Oracle WMS 的设备网络指南按已知来源放行并支持 HTTPS 打印。Dynamics 365 本地部署按角色明确必需的端口与证书。 [SAP EWM Security Guide](https://help.sap.com/doc/37b01ca687ce4276be47940f81df5192/9.4/en-US/SAP_Extended_Warehouse_Management_940_Security_Guide.pdf) · [Oracle WMS Network Configuration](https://docs.oracle.com/en/cloud/saas/warehouse-management/26d/owmms/oracle-wms-cloud-network-configuration.html) · [Dynamics 365 on-premises infrastructure](https://learn.microsoft.com/en-us/dynamics365/fin-ops-core/dev-itpro/deployment/configure-infrascripts-onprem)

部署沿用公司现有 HTTPS 入口。`APP_ORIGIN` 与业务访问地址和端口一致。若由反向代理转发且需识别原始客户端 IP，可将 `TRUSTED_PROXY_IPS` 设置为应用实际看到的上一跳代理 IP，并由代理覆盖转发头。入口日志格式见 [Nginx 模板](../deploy/nginx.conf.example)。上线时从业务终端核验登录，并根据公司防火墙策略检查数据库端口和运维入口的访问范围。

## 数据库保护与恢复

| 风险 | 软件交付与现场控制 |
| --- | --- |
| 传输窃听、伪装数据库 | 生产连接核验私网地址、目标库、TLS 证书链与服务身份。PostgreSQL 使用批准来源的 [访问规则模板](../deploy/pg_hba.wms.conf.example)。 |
| 凭证滥用、数据被篡改 | 分离运行和维护账号。生产启动拒绝持有额外角色、复制权限、库或 public 建对象权限、公共业务对象所有权的应用账号。应用仍需拥有办理业务所需写权限，须限制源地址、保护凭证并监控异常。 |
| 磁盘、快照或备份被复制 | 现场在数据库数据、WAL、附件与快照启用卷、磁盘或平台托管加密。备份工具直接加密 pg_dump 输出，采用 AES-256-GCM。密钥由公司密钥库托管，独立于数据库和备份存储。 |
| 删除、损坏和勒索攻击 | 保留独立权限域的加密不可变或离线副本。按现场恢复点目标配置加密 WAL 归档。在隔离库定期演练，核验表、迁移序列、附件和铜钴业务，记录实际恢复时长。 |

PostgreSQL 区分连接及存储加密。磁盘挂载期间仍须依靠访问控制和密钥保护。CISA 建议维护离线加密备份并定期验证恢复。 [PostgreSQL Encryption Options](https://www.postgresql.org/docs/16/encryption-options.html) · [PostgreSQL TLS Host Verification](https://www.postgresql.org/docs/16/libpq-ssl.html) · [CISA StopRansomware Guide](https://www.cisa.gov/sites/default/files/2025-03/StopRansomware-Guide%20508.pdf)

### 加密备份操作

在授权运维机使用与数据库兼容的 pg_dump 和独立生产维护配置。WMS_BACKUP_KEY_FILE 指向密钥库下发的私有文件，内容为 32 字节随机密钥的 64 位十六进制表示。使用新输出路径。轮换后保留恢复旧档所需的密钥版本。

    node scripts/database-backup.cjs backup /private/backup/wms-YYYYMMDD.enc
    node scripts/database-backup.cjs verify /private/backup/wms-YYYYMMDD.enc
    node scripts/database-backup.cjs decrypt /private/backup/wms-YYYYMMDD.enc /private/restore/wms.dump

解密先在目标目录的私有临时文件中验证。输出目录使用授权隔离的加密恢复卷，验证通过后在隔离库使用 pg_restore。附件、主机配置及 WAL 使用各自的受控备份作业。生产备份计划、离线副本和恢复演练由现场配置。

## 总经理审批

生产执行 211、212 号迁移后，通过 [总经理维护命令](../scripts/general-manager.cjs) 开通独立实名账号。维护服务单独读取账号配置和密码文件。生产 Compose 提供 general-manager 维护服务，先执行默认回滚预检，再追加 --apply 和 --confirm-database 及核对过的目标库名。密码轮换追加 --rotate。维护应用凭证和数据库运行凭证独立保管。

| 操作 | 生效方式 |
| --- | --- |
| 支持的账号岗位、数据范围、启停，账号开通、恢复和管理员代重置密码 | 提交总经理审批后生效。 |
| 注册申请的账号赋权，已有角色权限矩阵更新 | 提交总经理审批后生效。 |
| 普通资料更新、账号本人修改密码、已授权的账号应急软删除 | 沿用既有办理权限与审计。删除撤销会话，恢复走审批。 |
| 总经理账号 | 仅拥有授权审批能力。维护流程负责创建及密码轮换。 |

总经理在「系统管理 → 权限变更审批」核对岗位、权限或数据范围差异，验证当前密码后通过或驳回。提交人可查看和撤回本人的待办。生效前检查申请人授权及目标版本。目标或授权已变化的申请标记失效。审批和授权变更在同一事务提交，并撤销相关会话。待审代设置密码以散列暂存，申请结束即清除。生产待审请求在账号开通前可排队。TEST 在开通总经理后启用同流程。

## 系统日志与后续审计

服务器生成请求编号。生产结构化 HTTP 日志记录来源、时间、路径模板、状态、耗时、账号和故障编号。审计页面按分类、日期、结果和请求编号检索，详情展示脱敏字段。授权用户可以导出同一筛选范围内最多 2000 条 JSON 元数据证据。每次导出记录操作人、数量和 SHA-256 摘要。原有记录保留在受控审计库。

应用和反向代理日志汇集到独立安全平台，由安全运维设置留存与访问范围。重点监测重复拒绝、认证失败、审批失效、服务异常、备份失败和采集停止。各日志源需要同步时钟。 [OWASP Logging Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)

## 隔离 TEST 验证

- 本地应用以生产模式连接隔离 PostgreSQL，使用经验证的 TLS。两个模拟来源网段均可打开登录页并登录，登录事件可用请求编号追查，匿名访问受保护接口返回 401。
- 236 项全量回归通过。额外验证铜、钴产品上下文可办理同一权限变更申请，且并发审批只生效一次。
- PostgreSQL 16.14 加密备份完成解密、恢复及 190 张表逐表核对。恢复库通过应用启动、登录和铜钴查询。
- 公司生产的现有入口、证书、存储卷加密、日志采集与实名总经理开通由现场验收。
