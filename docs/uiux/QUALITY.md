# UI/UX 质量门禁与后续开发规范

## 提交前检查

- 新增或修改页面时，先选择既有页面骨架、组件和语义样式，再修改局部样式。
- 共享样式用设计变量表达字号、颜色、间距和控件尺寸。新增专用尺寸需要说明用途。
- 在相同语言、产品、角色和业务状态中比较界面。操作含义和权限相同的控件使用相同样式。
- 通过 Tab 检查焦点可见性、按键顺序和控件名称。复核正文对比度，确保状态可通过文字识别。
- 检查筛选、空状态、错误、长文本、历史数据和只读状态。检查桌面及窄屏溢出、遮挡、弹窗关闭和返回位置。
- 新路由、产品专用入口或关键状态补充到 `tests/release/uiux-routes.cjs`。
- 保存、审核、出库、打印、导出或权限相关改动增加对应业务回归。待确认的业务控件保留在原流程中。

## 可执行门禁

- `pnpm run test:uiux:static` 检查共享样式与静态路由登记。
- `pnpm run test:uiux` 用既有隔离 TEST fixture 扫描页面，生成覆盖数据及截图。
- `pnpm run test:uiux:gate` 检查已采集证据的路由覆盖、代表性页面的布局及可访问性指标。遗留例外采用精确页面和指标匹配。
- 代表性截图差异比较需要匹配截图环境。跨平台测试以布局和行为门禁为准。更新基准须逐页复核，记录对应修改和日期。

交付报告记录扫描数、实测数、截图数、问题修复和未覆盖原因。权限拒绝、缺少业务状态样本和正常渲染分别统计。
