# UI/UX 质量门禁与后续开发规范

## 提交前检查

- 开发前阅读[《穆松尼 WMS 全站设计规范》](DESIGN.md)。优先复用统一页面骨架、语义按钮、输入和表格组件。共享样式使用主题变量。扩展组件或新增业务例外时同步更新规范。
- 在提交说明登记受影响页面、适用产品、角色、状态及验证结果。使用既有 WMS TEST and UIUX quality gate 检查。
- 在同一产品、语言、角色及业务状态下对照验证。保存为主要动作，新增和返回使用次级操作。
- 核对键盘焦点、控件名称、文字对比度、空状态、加载失败和长文本。在 1280、1440 和 390 像素检查布局、筛选操作和弹窗。按[页面覆盖清单](COVERAGE.md)记录例外。
- 权限、历史单据 UUID、审批、库存事务及计量口径沿用原业务规则。产品界面和导出只展示适用字段。
- 路由或业务状态变更须同步审核 uiux-inventory.json、uiux-routes.cjs 和 uiux-matrix.cjs。更新截图须按图记录理由。

## 自动拦截

- 静态门禁检查设计令牌及场景登记。快速门禁覆盖核心页面和代表角色。完整门禁覆盖管理员及角色清单的中英文和登记视口。
- 路由登记为空、必测行缺失、落地地址或关键控件错误、截图缺失或尺寸与哈希不一致均失败。
- 横向溢出、操作和筛选裁切、无名称控件、重复标题、低对比度候选及钴产品生产批次字段均失败。误报须逐场景登记证据。
- 缺样本默认失败。例外必须写明场景、产品、角色、状态、原因和到期日。
- 故障注入用例覆盖删路由、缺行、缺样本、跳错页、假截图、无名称、重复标题、低对比度和裁切。
- 远端检查名称为 WMS TEST and UIUX quality gate。合并保护应使用同名检查，并保留仓库已有保护规则。推送独立分支即可运行同一提交；审批与部署不属于该工作流。
