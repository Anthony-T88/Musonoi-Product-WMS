# V4.7.3 部署评估与回滚

## 环境核验

- 本机 V4.7.2 运行在 4177，候选运行在 4180。候选库来自现有合成 TEST 的备份恢复，两个实例使用各自数据库。
- GitHub 默认分支 `release/v4.7.2` 为 `e8d0c4e6ddbecb07510e4506b14476b92bee6bbe`。与本机开发基线 `3e8f0d6d1a667828c1ba9f4cd42441af0d74eaea` 的运行目录及测试源码一致。
- 用户提供的线上公开接口报告 V4.7.2-ui1、TEST 和数据库健康。构建提交、真实库存与数据库迁移版本需要实例管理员提供核验依据。
- 已在本地模拟隔离环境验证迁移 CLI、备份恢复和启动。独立联网预生产实例待提供。当前候选的联网性能使用浏览器延迟模拟，实网登录及业务流程验收待安排。

## 迁移与核对

1. 确认目标为隔离预生产，核对应用来源、数据库环境、名称、连接地址和现行迁移校验和。使用既有迁移命令进行预演。
2. 保存目标库一致性备份和校验和。在独立数据库恢复备份并验证可读性，核对客户、合同、装车、许可证、库存、审批与用户数量。
3. 迁移 183 保留会话行，标记同账户被替代的旧会话，添加只允许一个当前会话的部分唯一索引。登录退出与替代写入既有审计表。
4. 迁移 184 保留 P3 历史子货位与几何数据，新增每仓库 P3 聚合位置及铜剩余捆包归属表。修复已有新生产入库区的地图关联。生产入库原位置编码和 P5 既有货位 ID 保留。
5. 核对备货、已装车、正式出库、P3、P5 和其他货位捆数。逐袋或逐捆抽查编号、净重、铅封和历史批次。核对钴产品库存与报表、许可证额度、既有发票编号及销售开票履约口径。
6. 对旧版本已经释放且目前仍实际堆在 P5 的捆包，按原释放记录和现场位置进行对账。迁移 184 保留这些历史实物位置。业务确认后通过受控流程处理差异。
7. 完成预生产并发、角色、弱网、数据库回滚演练及上线审批后安排正式发布窗口。

## 回滚条件

- 任一迁移校验和不符、启动后库存核对不平、会话发生越权、正式出库或许可证额度发生偏差，暂停发布并保留诊断及审计记录。
- 发布前回退使用已验证的 182 备份恢复到另一个库，再配套启动 V4.7.2。启动校验要求应用与迁移版本配套。
- 候选承接正式写入后，先保全新库存、审批、会话和单证记录，再决定向前修复或经业务批准迁移增量。回滚演练使用隔离库。
