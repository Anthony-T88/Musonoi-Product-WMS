# 历史出入库导入模板与验收

管理员从「历史出入库导入」选择铜或钴、选择拟导入业务类型、上传 Excel 并预览。实际日期有原单明确字段时由系统读取。只有发运日期时，填写经核实的实际业务日期和依据，再确认入账。

## 现场原件核对

| 产品与样本 | 工作表与明细范围 | 实际检查 |
| --- | --- | --- |
| 阴极铜，用户提供的 Commercial INV+PL `.xls` | `PL`，表头第 29 行，明细第 30–48 行，合计第 49 行 | 识别 19 捆，逐捆片数、编号、铅封及重量有效，重量合计与原单一致。 |
| 氢氧化钴，用户提供的 Commercial INV+PL `.xlsx` | `PL`，表头第 29 行，明细第 30–81 行，合计第 82 行 | 识别 52 袋，逐袋编号、铅封及重量有效，重量合计与原单一致。 |

原件都记录了 `Shipping Date`，实际出入库日期与入库依据需要现场核实。两份原件用于预览测试，入账、并发和纠错使用合成单据。原件和业务字段值保存在用户提供的本机附件中。

| 来源 | 映射 |
| --- | --- |
| `PL!E3/E4/E5` | 装箱单号、备货批次号、合同号 |
| `PL!E7` | 原装箱单发运日期，独立保留 |
| `PL!A22`，`PL!E22:E24` | 客户、车头、两挂车 |
| `PL!C30` 至合计前 | 捆包号或袋号，每个有效编号计为一件 |
| `PL!D30` 起 | 铜片数，钴模板没有该列 |
| `PL!E30` 起 | 铅封号，保留原始标识 |
| `PL!F30:G…` | 原单净重、毛重，单位 kg，合计与原表核对 |
| 实际日期 | 支持 D 列明确的 `Actual Inbound Date`／`Actual Receipt Date`／`Actual Outbound Date`／`Actual Dispatch Date` 及中译标题，取同一行 E 列。缺少时依据手工账、签收／交接凭证或管理员核实记录。 |

支持同一 `PL` 表头的 Excel 97–2003 `.xls` 和 `.xlsx` 文件，单文件最多 512 KB，每次预览一个装箱单。原始 `INV` 和 `Destination` 工作表随文件保存。宏、外部链接和嵌入对象的 XLSX 不可上传。样本 XLSX 附带标准打印机设置，校验只允许该类打印元数据通过。

同产品、同业务类型的有效单据按规范化装箱单号防重，单内按捆包或袋标识防重。不同历史单据重复登记同一件的同类业务会在行上标明。铜钴原件含发运日期时，入库仍须独立核实并选择入库。疑似与在线库存或装箱单重叠时，预览给出提示，确认请求要求完成核对。

入账记录原件、文件 SHA-256、原表行、日期依据、导入时间和管理员。整单事务写入，双击或网络重试返回原提交结果。纠错作废保留原件和历史，由管理员按核实后内容重新导入。历史台账独立于实时库存、许可证额度、正式出库及库存趋势。参见[专项测试结果](evidence/historical-import.json)。
